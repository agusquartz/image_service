# Code of Conduct

## Our Commitment

We want Image Service to be a welcoming, respectful, and productive open-source project.

Everyone participating in the project is expected to treat other contributors, users, maintainers, and community members with professionalism and respect.

This applies regardless of experience level, background, identity, nationality, language, religion, disability, appearance, gender identity, sexual orientation, or any other personal characteristic.

## Expected Behavior

Examples of positive and constructive behavior include:

- Being respectful when discussing technical decisions.
- Giving feedback about code and ideas rather than attacking people.
- Accepting that reasonable contributors may disagree.
- Asking questions in good faith.
- Giving others room to learn and make mistakes.
- Keeping discussions relevant to the project.
- Respecting maintainers' time and decisions.
- Acknowledging mistakes and correcting them.
- Helping maintain a collaborative environment.

Technical disagreement is welcome.

Personal hostility is not.

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, intimidation, or discrimination.
- Personal insults or degrading comments.
- Threats of violence or encouragement of harm.
- Sexualized language, imagery, or unwanted sexual attention.
- Deliberate misgendering or sustained disrespect toward someone's identity.
- Publishing another person's private information without permission.
- Repeated disruption of issues, pull requests, discussions, or reviews.
- Bad-faith arguments intended primarily to provoke or exhaust others.
- Spam, trolling, or intentionally inflammatory behavior.
- Retaliation against someone who reports a concern in good faith.
- Any other conduct that a reasonable person would consider inappropriate in a professional open-source project.

## Technical Criticism

Strong technical criticism is allowed and often useful.

For example:

> "This implementation can race when two writes target the same slot."

is appropriate.

Comments such as:

> "Only an idiot would write it this way."

are not.

Critique the implementation, design, assumptions, or evidence — not the person.

## Scope

This Code of Conduct applies to participation in project spaces, including:

- GitHub issues.
- Pull requests.
- Code reviews.
- Discussions.
- Commit or review comments.
- Project-related communication channels.
- Public interactions made while representing the project.

It may also apply to behavior outside these spaces when that behavior has a direct and substantial impact on the safety or participation of project contributors.

## Reporting a Conduct Issue

Please do not report Code of Conduct incidents through public GitHub issues.

A dedicated private reporting channel has not yet been established for this project.

Until one is available, please avoid including sensitive personal information in public project discussions. This section will be updated when a private reporting channel is established.

## Enforcement

Project maintainers are responsible for interpreting and enforcing this Code of Conduct.

Depending on the seriousness, frequency, and context of the behavior, maintainers may take actions including:

1. **Private clarification or warning**  
   The participant is informed that their behavior is inappropriate and is asked to stop.

2. **Public moderation**  
   Inappropriate comments, issues, discussions, or other content may be edited, hidden, locked, or removed where the platform permits.

3. **Temporary restriction**  
   The participant may be temporarily restricted from interacting with the project.

4. **Permanent removal**  
   The participant may be permanently blocked or banned from project spaces.

Severe behavior may result in immediate removal without a prior warning.

Enforcement decisions should consider context and should be applied consistently rather than based on whether the participant agrees with a maintainer's technical opinion.

## Appeals

A person affected by an enforcement decision may request reconsideration once a private reporting channel is available.

Submitting an appeal does not guarantee that the original decision will be changed.

## Good-Faith Participation

This Code of Conduct is not intended to suppress:

- Respectful disagreement.
- Technical criticism.
- Security research conducted responsibly.
- Decisions to reject a feature or pull request.
- Firm moderation necessary to keep project discussions productive.

The goal is to make it possible to disagree strongly about software while still treating people with respect.

## Maintainer Responsibility

Maintainers should:

- Avoid conflicts of interest when handling reports.
- Keep sensitive reports private where reasonably possible.
- Avoid retaliation.
- Document serious enforcement decisions privately when appropriate.
- Apply the same behavioral expectations to themselves.

## Security Reports Are Different

Security vulnerabilities should not be reported through the Code of Conduct process.

Please follow the instructions in [SECURITY.md](SECURITY.md) for vulnerability disclosure.

## Changes to This Code

This Code of Conduct may evolve as the project grows.

Material changes should be documented in the repository history so contributors can review how participation expectations have changed.
